# Коллекция запросов

Импортируйте [CreditPilot.postman_collection.json](CreditPilot.postman_collection.json)
в Postman либо совместимый локальный клиент. Облачная синхронизация не требуется.

1. Поднимите Compose и выполните `python demo.py` или `python seed.py` в backend.
2. В локальных переменных коллекции задайте `baseUrl`, `clientPassword`,
   `bankPassword` значениями вашего стенда. Не экспортируйте пароли, cookie или CSRF.
3. Cookie jar должен быть включён. Login автоматически сохраняет CSRF скриптом.
4. Запускайте одну из четырёх папок **целиком по порядку**, либо всю коллекцию.
   Скрипты сохраняют ID и версии между запросами. Каждая папка создаёт свою заявку;
   это позволяет повторять показ без очистки БД.
5. После login роль меняется для следующих запросов. Досье передаёт ID запроса,
   решения и рассчитанную меньшую сумму в последующие команды.

Ожидаемые завершения: три DISBURSED и один REJECTED. Во втором сценарии
присутствуют запрос, синтетический документ и повторный запуск проверки.
Последняя папка читает каталог, очередь, воронку и ML model card.

Коллекция предназначена для демонстрации HTTP-контракта. Проверки безопасности,
ошибок и гонок находятся в `backend/tests`; реальные пользовательские пути —
в `frontend/e2e`. При ручном повторе одной бизнес-команды сохраните исходный UUID
и тело: встроенный `{{$guid}}` при новом запуске создаёт новое намерение.

Автоматический прогон на одноразовом стенде: из корня `bash scripts/api-smoke.sh`.
Нужны Docker/Compose и npm; Newman скачивается из npm с фиксированной версией
6.2.1. Проверка не использует аккаунты или volume основного стенда. Порт 5183
должен быть свободен. После коллекции скрипт перезапускает backend и проверяет
сохранение трёх выдач и одного отказа.
