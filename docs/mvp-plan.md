# Состояние реализации и приоритеты

Ветка `feature/slava-dore` создана от `main` (`b4179d0`) по прямому запросу
пользователя. Предыдущие T01/T05/T06 использованы как основа; ORM-перенос T02
не выполнялся. Ниже описан текущий код, а не автоматически согласованная очередь задач.

| Направление | Состояние |
| --- | --- |
| Сессии/CSRF/владение, история, каталог и финансы | Сохранены и интегрированы с новыми сценариями |
| Клиентская анкета | Каталог, четыре шага, черновик, точные деньги, расчёт, submit, список и история |
| Банковское рассмотрение | Очередь/поиск/статусы, досье, команды и новая миграция |
| Проверки | Детерминированные источники, снимки, COMPLETE/INCOMPLETE/FAILED, безопасный повтор |
| Запрос уточнений/документа | Ограниченные поля, ответ клиента, TXT/CSV, сохранение предыдущих снимков |
| Скоринг | Decimal score_v1 и отдельная policy_v1; причины и допустимые условия |
| ML | Локальная логистическая регрессия, генератор, split, метрики, веса, объяснения/model card |
| Решение | Ручное предложение, меньшая сумма, обоснованный отказ |
| Оформление | Текст учебного договора, подтверждение и моделируемая выдача |
| Аналитика | Воронка, ожидание/задержки, журнал решений, сумма симуляций |
| Демонстрация | Четыре шаблона и идемпотентный seed; локальные материалы клиента |
| Комплект проверки | Backend/frontend/E2E, README, актуальные docs, OpenAPI, коллекция, notices |
| Публикация / commit / push / доступ жюри | Отдельное решение пользователя; автоматически не выполняются |

Фактические результаты прогонов фиксируются в [verification.md](verification.md).

Ближайший организационный шаг после локальной приёмки — пройти сценарий показа
с командой и решить, какую версию фиксировать для сдачи. Дополнительная инженерная
работа должна быть отдельным небольшим запросом: например, идемпотентность POST
создания, аудит входов/просмотров, отказ клиента от предложения или усиление
авторизации. Не добавлять инфраструктуру и новые модели без доказанной пользы.
