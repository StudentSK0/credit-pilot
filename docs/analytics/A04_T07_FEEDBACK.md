## 2. Какие текущие поля достаточны

**Вывод: новые обязательные поля клиентской анкеты для A04 не нужны.**
Девять существующих полей плюс серверные данные и локальные источники достаточны
для первичного учебного рассмотрения. Это не полнота реального банковского досье.

| Поля, IMPLEMENTED | Для чего используются | Рекомендация и причина | Влияние frontend/backend | Источник |
| --- | --- | --- | --- | --- |
| company_name, inn | Идентификация синтетической записи | MUST: сохранить имена/типы; ИНН string с ведущими нулями | FE: существующие inputs; BE: без расширения схемы | T05, BRV01/02 |
| credit_purpose | Контекст оборотных средств/оборудования | MUST: существующий текст, без новой классификации/парсера | FE: поясняющая подпись; BE: прежний лимит 1000 | T05, BRV04 |
| product_code | Выбор учебного продукта | MUST: код из серверного каталога, без ручного списка условий | FE: каталог; BE: уже GET products | T05 |
| amount, term | Запрошенные условия | MUST: RUB и целые месяцы, включительные границы | FE: отображение/валидация; BE: сервер остаётся источником проверки | T05, BRV04 |
| monthly_revenue, monthly_operating_expenses, existing_monthly_debt_payments | Входные месячные финансы | MUST: R>0, E/D≥0 при submit, ноль вводится явно | FE: три существующих поля; BE: не менять правила | T05, BRV03, A03 |
| product_version | Закреплённая версия условий | MUST: только чтение результата; **не десятое поле ввода** | FE: исключить из POST/PATCH; BE: уже фиксирует при submit | C/T05, конфликт старых предложений A01/A02 |

Все четыре денежных поля — конечные Decimal, ≤2 знаков, без округления;
рекомендуемый payload — десятичные строки, ответы уже строки. `term` — JSON
integer, не строка. DRAFT может быть неполным; submit проверяет обязательность
и бизнес-границы. Не запрещать E>R или нулевые E/D и не вставлять нули вместо null.

не редактирует. Источник исправляет команда демо новой версией, затем сотрудник
запускает новый run. Случайных результатов при открытии экрана нет.
