# Модели риска и кредитная политика

Все формулы, признаки, ставки и пороги ниже — **Предложение команды**.
Результат учебный. Банковская точность, регуляторное соответствие и применимость
к реальным заёмщикам не заявляются.

## Балльная модель score_v1

Входы: месячные выручка R, операционные расходы E, текущие выплаты D;
запрошенные сумма A и срок n; ставка сохранённой версии продукта; возраст M
и максимальная просрочка O из локальных источников.

`P=A*r/(1-(1+r)^(-n))`, `r=annual_rate/12` (при r=0: `P=A/n`).
`DSCR=(R-E)/(D+P)`, `margin=(R-E)/R`.
Расчёт Decimal precision=50. Для порогов используется полный результат, только
показ платежа округляется HALF_UP до копеек.

| Фактор | Интервалы | Баллы |
| --- | --- | --- |
| Покрытие платежей DSCR | <1 / [1,1.2) / [1.2,1.5) / ≥1.5 | 0 / 15 / 30 / 40 |
| Возраст, полные месяцы | <6 / 6–11 / 12–23 / ≥24 | 0 / 5 / 10 / 15 |
| Маржа | <0.10 / [0.10,0.20) / ≥0.20 | 0 / 10 / 20 |
| Максимальная просрочка, дни | 0 / 1–30 / >30 | 25 / 10 / 0 |

LOW: ≥75, MEDIUM: 50–74, HIGH: <50. Баллы не являются вероятностью дефолта.

## Политика policy_v1

Предложение требует полных согласованных данных, активной регистрации,
просрочки ≤90 дней, DSCR ≥1.2 и риска LOW или MEDIUM. Комментарий сотрудника
обязателен для любого решения. Неизвестный источник не считается хорошим.
При INCOMPLETE нельзя отказывать «за высокий риск»; подтверждённая неактивность
регистрации допускает отдельный отказ по допустимости продукта.

Причина отказа проверяется по фактам: AFFORDABILITY при DSCR<1.2,
CREDIT_HISTORY при известной просрочке, HIGH_RISK при HIGH,
INACTIVE_BUSINESS при неактивной регистрации. Это допустимость ручного решения,
не автоматический отказ. Название/ИНН должны совпасть с локальным fixture.

Меньшая сумма при том же сроке вычисляется из максимального платежа
`(R-E)/1.2-D`. Округление суммы вниз, проверка минимум/максимум продукта,
новый расчёт и политика обязательны. Первоначальная сумма не меняется.

## ML: synthetic_logit_v1

Цель — учебная вероятность события «просрочка >30 дней в следующие 12 месяцев».
Признаки — DSCR, margin, business_age_months, max_overdue_days. Нет статуса,
решения сотрудника, номера клиента, ИНН или признаков после принятия решения.

Обучение: [train.py](../backend/ml/train.py), inference:
[inference.py](../backend/ml/inference.py), веса: [model.json](../backend/ml/model.json),
полный отчёт: [metrics.json](../backend/ml/metrics.json).

- 6 000 независимых синтетических компаний, seed `20261023`.
- Метки сэмплируются из раскрытого вероятностного механизма с ненаблюдаемым
  случайным шоком. Они не являются готовым результатом score_v1.
- После перемешивания: 4 200 train, 900 validation, 900 test. Одна компания —
  одна строка, зависимых наблюдений между частями нет. Отложенный тест не участвует
  в подборе параметров/порога. Нормализация только по train.
- Логистическая регрессия, batch gradient descent, L2, фиксированное число эпох.
  Весь цикл использует стандартную библиотеку Python; внешней runtime-зависимости нет.
- Признаки ограничены документированными диапазонами в `features()`. Веса и scaler
  хранятся в JSON, pickle не используется. Данные/веса воспроизводятся одной командой.
- Порог для confusion matrix выбран на validation по balanced accuracy. Он не
  используется для автономного кредитного решения.

Отчёт содержит ROC-AUC, average precision (ступенчатая PR-AUC), Brier,
confusion matrix, calibration bins и константный baseline. Метрики интерфейс
читает из сохранённого отчёта; они не придуманы для демонстрации.

**Ограничение:** модель учится приближать синтетический генератор. Хорошие метрики
на такой выборке не доказывают качество на настоящих компаниях, отсутствие
смещения или правильность реальной вероятности. Нет внешней валидации,
проверки fairness, временного drift или реальных кредитных исходов.

Вклад признака — `coefficient * (value - train_mean) / train_scale`, в единицах
логарифма шансов. Положительный вклад повышает прогноз относительно baseline,
отрицательный снижает; это объяснение модели, не причинное доказательство.
В досье сохранены исходная анкета, внешние признаки, модель/версия признаков,
прогноз и вклады. После обновления данных старые снимки сохраняются.

ML используется как дополнительный взгляд сотрудника. Итог определяется
отдельной кредитной политикой и ручной командой с понятным клиенту объяснением.
Обоснование ценности: показать, как будущая валидированная модель может быть
заменена локальным версионированным компонентом, сохранив процесс и аудит.
