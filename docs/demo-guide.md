# Показ и воспроизводимые сценарии

Запуск и аккаунты: [README](../README.md). Для двух ролей используйте разные
профили браузера (обычное/инкогнито). Все данные синтетические, операции моделируются.
При seed `python demo.py` четыре заявки уже отправлены. Для полного показа
анкеты создайте новый экземпляр сценария с главной клиента.

## 1. Пекарня: исходное предложение и выдача

- Клиент: «Пекарня открывает вторую точку», ИНН 7700000001, 600 000 ₽, 18 мес.
  Проверьте шаги, сохранение, reload, расчёт платежа и отправку.
- Сотрудник: очередь → заявка → «Запустить проверки». Реестр: активна,
  48 месяцев; просрочка 0. Вкладка риска показывает факторы и ML.
- Обзор → предложение исходной суммы → написать содержательное объяснение → отправить.
- Клиент открывает договор, подтверждает демонстрационное подписание.
- Сотрудник моделирует выдачу. В обоих кабинетах DISBURSED, в истории — события
  с авторами, временем и версиями. Обновление страницы сохраняет результат.

## 2. Мастерская: уточнение и документ

- ИНН 7700000002, оборудование 900 000 ₽ / 24 мес.; в расходах 540 000 ₽
  содержится разовая покупка. Сотрудник запускает проверки и изучает нагрузку.
- «Уточнить»: оставить поле «Операционные расходы», документ «Финансовый отчёт».
  Вопрос: «Уточните регулярные расходы без разовой покупки и приложите отчёт».
- Клиент: расходы `400000.00`, пояснение об исключении разовой покупки,
  файл [financial-report.csv](../frontend/e2e/fixtures/financial-report.csv).
  Можно сформировать учебный текст прямо в форме; это демонстрационный документ,
  не независимая верификация цифр. Отправить ответ.
- Банк: повторить проверки. Новый run содержит новые расходы, прежний — 540 000 ₽.
  Файл открывается через защищённый endpoint. Дальше предложение/подпись/выдача.

## 3. Логистика: понятный отказ

- ИНН 7700000003, 800 000 ₽ / 18 мес.; просрочка 65 дней, высокая нагрузка.
- Изучить факторы, ML и ограничения. Выбрать «Отказать», основание
  «Кредитная история», текст с конкретными фактами. Не подменять решение словом «AI».
- Клиент видит REJECTED и понятную причину. Журнал решений показывает автора.

## 4. Магазин: встречная сумма

- ИНН 7700000004, запрос 1 500 000 ₽ / 24 мес.
- Исходный DSCR недостаточен. Вкладка риска показывает рассчитанную меньшую
  сумму и новый платёж с DSCR≥1.2; исходный запрос остаётся отдельным.
- В обзоре предложенная сумма уже заполнена расчётом. Объяснить уменьшение,
  отправить. Клиент сравнивает обе суммы, принимает условия; банк завершает симуляцию.

## Негативные проверки

| Действие | Ожидаемый результат |
| --- | --- |
| `600000.001` в сумме | Отклоняется, не округляется |
| CLIENT B открывает номер CLIENT A | 404; нет чужой заявки, истории и документов |
| CLIENT вызывает checks/decision/disburse | 403 |
| Нет CSRF / неверный Origin | 403; состояние не меняется |
| Несовместимый статус или устаревшая версия | 409; UI предлагает обновить |
| Повтор новой команды с тем же UUID и payload | Первоначальный результат; нет двойного события/договора/выдачи |
| Ответ меняет не запрошенное поле | 422; запрос и заявка не меняются |
| Запрошен документ, но файл отсутствует | 422 |
| ИНН `9999999999` | NO_DATA, INCOMPLETE без оценки; нет выдуманного риска |
| ИНН `7700000099` | FAILED / SOURCE_UNAVAILABLE; повтор сохраняет историю попыток |
| Несовпадение названия и fixture | ISSUE; уточнение названия вместо молчаливой замены |
| Рестарт после старта проверки | RUNNING можно повторить после 30 с; прежний помечается INTERRUPTED |
| Повтор `python demo.py` | Пройденные сценарии и данные не сбрасываются |

Backend-тесты проверяют транзакции, права, версии, миграции и сценарии на временной
БД. Playwright через `scripts/e2e.sh` проходит четыре сценария и дополнительно
черновик/точность/reload/мобильную ширину/чужой маршрут в изолированном окружении.
Общий health сохраняет 200/503; проверка остановки БД выполняется только на тестовом стенде.
