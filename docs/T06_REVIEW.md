# T06 — интерфейс, серверная сессия и навигация

Состояние на 23 октября 2026 года. Ветка `feature/t06-frontend-login`.
Реализация подготовлена к публикации отдельными коммитами кода и документации;
объединение в main выполняется через отдельный PR после ревью.

## Результат и границы

Реализованы вход и выход через существующий backend, bootstrap через `/api/me`,
восстановление CSRF той же вкладки, Layout и отдельная навигация для CLIENT
и BANK_EMPLOYEE. Состояния загрузки, ошибок, недоступного backend и потери CSRF
показываются явно. В кабинете выводятся только id/role/company_id из auth API.
Пароль остаётся только в форме до завершения запроса; в storage он не записывается.

Frontend использует React/TypeScript/Vite, Tailwind и локальные Button/Input
по подходу shadcn с CVA. Светлый кабинет, тёмный блок входа, коралловый акцент,
адаптивная боковая навигация. Есть подписи учебного прототипа, семантические
формы/сообщения, видимый keyboard focus, Escape для мобильного меню и reduced motion.
Это реализация UI; визуальная проверка в браузере пока не выполнена.

Каталог, «Мои заявки» и обработка заявок — заготовки с пометкой «В разработке».
Нет фиктивных заявок, решений, финансовых показателей или списка «0 заявок».
Запросов к ещё не подключённым API T05, форм T07, скоринга и банковских команд нет.
Backend, миграции, API-контракты и Compose-файл не изменялись.

## Проверки

`npm ci`, `npm test`, `npm run build` выполнены в `node:24-alpine`.
Системный Node 18 для текущего Vite/Vitest не подходит; рекомендуется Node 24,
как в существующем frontend Dockerfile.

20 тестов проходят: вход обеих ролей и разные меню, игнорирование роли
из localStorage, cookie-настройки запросов, восстановление кабинета через `/me`,
отправка CSRF при logout и очистка после него, отсутствие/ошибка CSRF с повторным
входом, сохранение кабинета при ошибке logout, 401 и истечение сессии, повторный
bootstrap, чужой маршрут, явные заглушки без запросов к T05, ошибки 401/403/422,
offline и retry, неизвестная роль, загрузка, Escape в меню, поздний 401 от старой
проверки, восстановление CSRF из storage и работа в памяти при его запрете.

Эти тесты используют jsdom и подменяют HTTP; они не являются браузерным E2E.
Отдельно выполнены настоящие HTTP-проверки с PostgreSQL:

- nginx отдаёт HTML/JS/CSS с HTTP 200, `/api/health` через proxy возвращает 200.
- CLIENT и BANK_EMPLOYEE действительно входят через `/api/auth/login`.
- Сервер устанавливает HttpOnly cookie; `/api/me` возвращает соответствующую роль.
- Новый HTTP-клиент с той же cookie продолжает сессию без повторного login.
  Это проверка сохранения серверной сессии, не перезагрузка браузера.
- Logout без CSRF/с неверным CSRF отклонён с 403; с корректным — 204.
  Повторный `/api/me` с сохранённой до выхода cookie даёт 401: проверен именно
  отзыв серверной сессии, помимо удаления cookie из HTTP-клиента.
- Неверные учётные данные дают 401, невалидный login payload — 422.

Финальная HTTP-проверка выполнена на отдельном Compose-проекте
`credit-pilot-t06-check` с изолированной БД, frontend 5183/backend 8010.
Пароли созданы локально, не записаны в Git и не выведены в отчёт. Основной
Compose-стенд и его volume не очищались. Из-за недоступности Docker Registry
для повторной backend-сборки использован существующий локальный образ:
SHA-256 основных Python-модулей совпал с файлами этой ветки. Frontend-образ собран
из текущих файлов обычным Dockerfile. Код backend и миграции не редактировались.
После проверок отдельный стенд остановлен, его volume сохранён.

## Ограничения и следующий шаг

Инструмент управления браузером вернул пустые списки приложений и браузеров.
Визуальная оценка desktop/mobile, фактический reload вкладки, Back/Forward
и полный браузерный путь вход/выход не выполнены. Для ручного прогона используйте
обычный запуск из README и локальные seed-аккаунты.

Сессия без CSRF допускает просмотр, но перед изменениями/выходом нужен повторный
вход. При смене общей cookie в другой вкладке старый CSRF определяется только
по серверному 403; команда автоматически не повторяется. SessionStorage доступен
JS и не защищает от XSS. При его запрете токен остаётся в памяти до reload.
Повторный login создаёт новую сессию; отзыв всех прежних сессий backend не реализует.

Ближайший небольшой шаг — браузерная приёмка T06 обеими ролями, включая reload,
потерю CSRF и мобильное меню. Подключение каталога/форм заявок — отдельная T07
после готовности и согласования API T05.
